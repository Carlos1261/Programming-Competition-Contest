EDITORIAL: HABANA ALMENDRON ROUTES

1. PROBLEM ANALYSIS
This is an NP-Hard optimization problem. With N=12, the state space is roughly 3^12 * (R*C), which is ~17 million states. A simple BFS or Dijkstra is too slow for the 2.0s limit.

2. SUBTASK HINTS
- Subtask 1 (N <= 8, No Patience): Use standard DP with bitmask. The state is (mask_picked, mask_delivered, pos). Since time isn't an issue, focus on the cheapest path for the highest pay.
- Subtask 2 (CAP = 1): This simplifies the problem to a sequence of individual trips. You can solve it as a Traveling Salesperson Problem (TSP) variation where each "node" is a pair (Pickup -> Dropoff).
- Subtask 3 (Full Constraints): Requires a heuristic approach. Beam Search is ideal here, keeping only the top W most promising states at each step.

3. THE "WALKTHROUGH" (Sample #1 Example)
- Taxi starts at (0,0).
- POIs: Pickup '1' at (1,2), Dropoff 'A' at (4,2).
- Route:
  1. (0,0) -> (1,2): 3 moves. T=3. Passenger '1' has patience 20. 3 <= 20? YES. Pickup successful.
  2. (1,2) -> (4,2): 3 moves. T=6. Dropoff 'A' at (4,2). Money += 100.
  3. (4,2) -> (0,0): 6 moves. T=12. Return to start.
- Final Result: 100 pesos, 12 moves (including return).

4. ADVANCED OPTIMIZATIONS
- Pareto Frontier: If two states have the same passengers at the same location, the one with MORE money and LESS time always wins. Prune the other.
- State Pooling: Pre-allocate memory for states to avoid slow 'new' or 'push_back' operations during the search.
- Preprocessing: Running Dijkstra from each POI to every other POI allows us to "jump" between important nodes in O(1) during the Beam Search.

COMPLEXITY:
- Preprocessing: O(P * RC log RC) where P is the number of POIs.
- Main Search: O(BeamWidth * N^2).
5. THE WINNING HEURISTIC (The "Secret Sauce")
Standard Beam Search often fails because it greedily picks the most money *now*, ignoring that a slightly longer trip might yield much more money *later*.
Our solution uses a Hybrid Efficiency Score to rank states:
   
   Score = Total_Money / (Time_Elapsed ^ 0.8)

- Why ^0.8? A linear division (Time ^ 1.0) is too aggressive against long trips. 
- Using 0.8 allows the taxi to take longer, high-reward routes (like in Test Case #11) without being pruned early.
- We pre-calculate this power table to ensure O(1) scoring during the search.

6. ALTERNATIVE APPROACHES (Why they fail)
A. Dynamic Programming (DP)
   - State: dp[mask_picked][mask_dropped][pos][time]
   - Complexity: O(4^N * POIs * TMAX). 
   - Verdict: Feasible for Subtask 1 (N=8), but Memory Limit Exceeded for N=12.

B. Simulated Annealing (SA)
   - Strategy: Randomly swap passengers in a route.
   - Verdict: The grid contains walls ('#'). Random changes often create invalid paths or get stuck in local optima. It is too unstable for the strict 2.0s limit.

7. EDGE CASES HANDLED
- "The Round Trip": The solution explicitly checks paths returning to (START_R, START_C) at every step.
- "The Lazy Taxi": We force the Beam Width to remain high (6000) for at least 1.5s to prevent early convergence on suboptimal short routes (Test Case #7).


ALGORITHM: HYBRID BEAM SEARCH (Habana Almendron)

1. PRECOMPUTATION PHASE (Graph Compression)
   Input: Grid RxC, N Passengers.
   Identify POIs (Points of Interest): Start + Pickup locs + Dropoff locs.
   
   // Pre-calculate Power Table for O(1) scoring
   For t in 0 to 3000:
       TimeFactor[t] = Pow(t + 1, 0.8)

   // Convert Grid to Adjacency Matrix
   For each POI u:
       Run BFS on Grid to find shortest paths to all other POIs v.
       Store DistMatrix[u][v] and PathReconstruction[u][v].
       (This avoids running BFS during the main search).

2. SEARCH INITIALIZATION
   RootState = { 
       Location: Start, 
       Time: 0, 
       Money: 0, 
       Load: 0, 
       Masks: 0 
   }
   Beam = { RootState }
   BestMoney = 0

3. MAIN LOOP (Beam Search)
   While Beam is not empty AND RealTime < 1.9s:
       Candidates = []
       
       For each State S in Beam:
           // A. Try Closing the Loop (Return to Start)
           If S.Location != Start:
               Calculate trip home.
               If valid within T_MAX:
                   Update BestMoney.

           // B. Expand to Neighbors (Transitions)
           For each POI v in Graph:
               If v == S.Location OR time to reach v exceeds T_MAX: 
                   Continue
               
               NewState = Copy(S)
               Travel to v: NewState.Time += DistMatrix[S][v]
               
               // Simulation Logic
               1. Drop off passengers destined for v.
               2. Pick up passengers at v (Greedy by Pay, check Cap & Patience).
               
               // --- THE SECRET SAUCE (Heuristic Scoring) ---
               Potential = EstimateFutureEarnings(NewState)
               TotalValue = NewState.Money + Potential
               
               // Hybrid Efficiency Score: Money per (Time^0.8)
               Priority = TotalValue / TimeFactor[NewState.Time]
               
               Add {NewState, Priority} to Candidates

       // C. Pruning (Selection Phase)
       // Keep width high (6000) for 1.5s to explore deep paths, then narrow to 2000
       CurrentWidth = (Elapsed > 1.5s) ? 2000 : 6000
       
       If Candidates.size > CurrentWidth:
           Select top CurrentWidth states using Nth_Element (O(N)) based on Priority.
       
       Beam = Selected Candidates (Sorted)

4. OUTPUT
   Reconstruct path from BestMoney state using Parent Pointers.
   Print TotalMoney and Step-by-Step Coordinates.
